# Repository conventions

## Commits and pull requests

Do not add AI attribution trailers, footers, or "generated by" stamps to commit
messages, pull request descriptions, or PR/issue comments in this repository
(e.g. no `Co-Authored-By: Claude ...`, no `Claude-Session:` links, no
"Generated with Claude Code" lines). This project is public-facing and the
maintainer does not want commit/PR history to read as AI-stamped.

## Versioning

Version numbers follow `MAJOR.MM.PP`, where `MM` (minor) and `PP` (patch) are
always two digits (e.g. `0.07.00`, not `0.7.0`). This keeps tags sorting
correctly once either number passes 9 (`0.09.00` < `0.10.00`, not `0.9.0` <
`0.10.0` sorting as `0.10.0` < `0.9.0` under plain lexicographic ordering).

`MM` increases for new tools or features, `PP` for fixes and cleanup with no
new functionality, matching the scheme already documented at the top of
`CHANGELOG.md`.

On every release cut:
1. Rename the `## [Unreleased]` section in `CHANGELOG.md` to
   `## [MAJOR.MM.PP] - YYYY-MM-DD`, and add a fresh empty `## [Unreleased]`
   above it for the next round of work.
2. Tag the release commit: `git tag -a vMAJOR.MM.PP -m "vMAJOR.MM.PP - <short summary>"`.
3. Push the tag: `git push origin vMAJOR.MM.PP`.
